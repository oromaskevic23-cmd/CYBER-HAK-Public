## Engineering change

This extends the existing CYBER HAK AuditShield v0.2 PR without modifying or weakening its anonymous GitHub scanning or existing Artifact Guard / Policy Gate.

- `src/orion-guardian-gate.mjs` independently checks signed, bounded public ORION advisory claims against a public-key registry pinned by the caller.
- Each Ed25519 signature is verified over canonical exact claim fields from the actual ORION v0.1 protocol; a syntactically valid SHA alone is not trusted as provenance.
- Every report field, SHA-256 report self-digest, claimed domain, NCA agent ID, stance, summary digest, signed evidence digests, source payload digest and contradiction classification are cross-checked.
- Distinct trusted domain key fingerprints, agent identities, per-claim domain uniqueness, timestamps and bounded 2–32 advisory count are enforced. The resulting status is `HUMAN_REVIEW_REQUIRED` or `DENY`, never task execution or production approval.
- An owner HALT indicator overrides otherwise valid signatures. Invalid/missing input fails closed. Raw source text, signatures or private keys are not copied to receipts.
- The trust registry is a **provided public-key configuration**, not autonomous agent enrollment or proof that a key belongs to the IMPERIAL Core owner.

## Exact pinned cross-repository verification

`integration/orion-guardian-pinned.test.mjs` runs the actual public ORION implementation at immutable SHA `f2dd1d0d6da4ae899c66c5078ce571d4385c0224` (ORION PR #3) through its own `OrionAdvisory` source and `verifyOrionReport` module.

The GitHub Actions job `guardian-orion-contract` checks out CYBER HAK's current PR head and separately read-only fetches the exact ORION revision, then executes `npm run orion:guardian` on Node 22.

Adversarial checks include tampered or wrong-key signatures, contradictory claims, replayed/duplicated nonce-domain input, owner halt, source-evidence mutation even with a rehashed report, missing advisory coverage, expired claims, domain-key impersonation, tampered approval state and redacted receipts.

## Trust boundaries and deliberately blocked features

| Boundary | Verified here | Not verified / denied |
|---|---|---|
| ORION | Actual signed advisory source and independent verification of report consistency | Semantic truth of assertions, evidence bytes or agent inference |
| CYBER HAK | Local fail-closed safety inspector callable by higher layers | A deployed Guardian Core enforcement point |
| Agent domains | Pinned Ed25519 public keys with distinct fingerprints | Actual institutional key enrollment, revocation and proof of human owner authority |
| HANTER / LEGION / NCA | Contract-compatible ORION signed report | Live service-to-service authentication or process control |
| Approval Gateway | Always `NOT_GRANTED` | Production permit issuer or separate human approval |
| Audit Ledger | No raw source in local receipt | Persistent, centralized, tamper-evident remote evidence pipeline |
| ProofGraph | Digest consistency of signed advisory envelopes | Release proof-carrying chain or independently verified evidence contents |
| Scale | Bounded 2–32 statements per inspection | Billion running NCA or collective live LLM execution |

**The protector cannot deploy, release, pay, modify user data, assign agents, approve missions or access private repos.** Replay prevention applies only to each inspected submission collection; no persistent anti-replay service is installed. Signatures are generated by ephemeral test keys. CI success demonstrates offline code-level compatibility only.

**Reproduction:** On the PR branch run `npm ci --ignore-scripts --no-audit --no-fund && npm run verify`. For the pinned integration command `npm run orion:guardian`, ORION source must already be present at `orion_public_reference/src/*.mjs` exactly as CI checks out; otherwise it fails closed.
